# Task Engine — Discovery (issue #7)

## Goal

Define a **common task engine** that aggregates manual tasks (created by operators) and
automatic tasks (generated by rules from domain state: vaccines, treatments, vet reviews,
sterilization, microchip, deworming, foster follow-ups, post-adoption, documentation,
administrative).

This engine **feeds the dashboard/home pending cards** — it does not replace them.

---

## Decisions already closed (issue #7, 2026-07-31)

| Decision | Value |
|---|---|
| Home shows actionable pending cards | Yes — dashboard queries `tarea.estado = 'pendiente'` |
| Manual and automatic tasks share common model | Yes — same `tarea` table, `tipo` distinguishes source |
| Common fields | `origin`, `type`, `priority`, `state`, `responsible`, `due date`, `link to animal/process` |

## Task model

### Table: `tarea`

| Column | Type | Notes |
|---|---|---|
| `id` | UUID | PK, `gen_random_uuid()` |
| `tipo` | TEXT | `manual` \| `automatica_*` subtypes (see below) |
| `origen` | TEXT | `dashboard_manual` \| `regla_salud` \| `regla_acogida` \| `regla_adopcion` \| `regla_documentacion` \| `regla_administrativa` |
| `prioridad` | TEXT | `baja` \| `normal` \| `alta` \| `urgente` |
| `estado` | TEXT | `pendiente` \| `en_progreso` \| `completada` \| `cancelada` \| `vencida` |
| `responsable_id` | UUID | nullable — unassigned tasks are allowed |
| `vencimiento_at` | TIMESTAMPTZ | nullable — no deadline is valid |
| `vinculo_tipo` | TEXT | `animal` \| `voluntario` \| `entrada` \| `acogida` \| `adopcion` \| `documento` |
| `vinculo_id` | UUID | ID of the linked entity |
| `metadata` | JSONB | extensible per-task-type payload |
| `created_at` | TIMESTAMPTZ | |
| `updated_at` | TIMESTAMPTZ | |

**CHECK constraints** enforce all enum values at the database level.

### Task types (`tipo`)

| Value | Description |
|---|---|
| `manual` | Operator-created task |
| `automatica_vacuna` | Vaccine expiration warning |
| `automatica_tratamiento` | Active treatment follow-up |
| `automatica_revision` | Vet review due |
| `automatica_esterilizacion` | Sterilization due |
| `automatica_microchip` | Microchip registration due |
| `automatica_desparasitacion` | Deworming due |
| `automatica_seguimiento_acogida` | Foster follow-up |
| `automatica_seguimiento_post_adopcion` | Post-adoption follow-up |
| `automatica_documentacion` | Documentation incomplete |
| `automatica_administrativa` | Administrative task |

## Rule engine

### Implemented stubs (MVP — first 3)

| Rule | Trigger | Priority | Target |
|---|---|---|---|
| `rule_vacuna_vencimiento` | Vaccine expires in <7 days | alta | `vinculo_tipo=animal` |
| `rule_seguimiento_post_adopcion` | Adoption >30 days old, no follow-up | normal | `vinculo_tipo=adopcion` |
| `rule_esterilizacion_pendiente` | Male animal >1 year, no sterilization record | normal | `vinculo_tipo=animal` |

All rules return `list[TareaDraft]`. The caller decides when and how to persist them.

### Deferred rules (future MVC)

The discovery scope identified additional automatic task sources not yet implemented:

- Active treatments with end date passed (`automatica_tratamiento`)
- Vet reviews scheduled but not completed (`automatica_revision`)
- Microchip registration pending after intake (`automatica_microchip`)
- Deworming schedule (based on species/weight interval) (`automatica_desparasitacion`)
- Foster placement follow-up at configurable intervals (`automatica_seguimiento_acogida`)
- Documentation completeness check per adoption (`automatica_documentacion`)
- Administrative task generation from workflow state (`automatica_administrativa`)

## Coexistence with counters

Counters (e.g. "3 vaccines expiring soon") are **aggregate read models** computed
from the `tarea` table — they are not duplicated state.

The task engine creates individual `tarea` rows. The dashboard counter query is:

```sql
SELECT COUNT(*) FROM tarea
WHERE estado = 'pendiente'
  AND vinculo_tipo = 'animal'
  AND tipo = 'automatica_vacuna'
  AND vencimiento_at < NOW() + INTERVAL '7 days';
```

No shadow table, no separate counter maintenance — same source of truth.

## Dashboard integration

Dashboard pending cards query `tarea.estado = 'pendiente'` with optional
`responsable_id = :current_user` filter.

```
GET /tareas?estado=pendiente&responsable_id=<me>
```

Returns tarea rows sorted by:
1. Priority bucket (urgente → pendiente → en_progreso → completada → cancelada → vencida)
2. `vencimiento_at ASC NULLS LAST`
3. `created_at DESC`

## API surface (service layer)

```python
# Create
crear_tarea(client, tipo, origen, *, prioridad, responsable_id, ...) -> str  # tarea_id

# Read
listar_tareas(client, *, estado, responsable_id, vinculo_tipo, vinculo_id, limit, offset) -> list[Tarea]
obtener_tarea(client, tarea_id) -> Tarea | None

# Transition
actualizar_estado(client, tarea_id, nuevo_estado) -> Tarea
asignar_tarea(client, tarea_id, responsable_id) -> Tarea
cerrar_tarea(client, tarea_id, comentario) -> Tarea
```

All SQL lives in `app/modules/tasks/queries.py` (query/service separation — AGENTS.md §22).

## Discovery scope: data sources that generate tasks

| Domain | Entity/Field | Automatic task triggered |
|---|---|---|
| Health | `vacuna.fecha_vencimiento` | `automatica_vacuna` — 7 days before |
| Health | `tratamiento.fecha_fin` | `automatica_tratamiento` — on pass |
| Health | `revision_veterinaria.fecha_programada` | `automatica_revision` — when due |
| Health | `animal.sexo=macho` + age >1yr | `automatica_esterilizacion` — after birthday |
| Health | `microchip.registrado=false` | `automatica_microchip` — after intake |
| Health | `desparasitacion.proxima` | `automatica_desparasitacion` — on schedule |
| Foster | `acogida.fecha_inicio` + interval | `automatica_seguimiento_acogida` — configurable |
| Adoption | `adopcion.fecha_adopcion` + 30 days | `automatica_seguimiento_post_adopcion` — without follow-up |
| Documents | `adopcion.documentacion_completa=false` | `automatica_documentacion` — on adoption creation |
| Admin | workflow state transitions | `automatica_administrativa` — from rule engine |
